COMO O COMPORTAMENTO MUDA

Não existe uma única forma de “ser agente”

Arquiteturas diferentes usam estados, objetivos e antecipação de formas distintas.

REACTIVE

Reage ao presente

Observation → policy → action. Rápido e local.

MODEL-BASED

Mantém estado interno

Combina novas observações com uma representação do mundo.

GOAL-DIRECTED

Persegue estados desejados

Escolhe ações considerando o que aproxima do objetivo.

UTILITY-DRIVEN

Compara trade-offs

Custo, tempo, risco e qualidade diferenciam caminhos válidos.

Comportamento é consequência da política de decisão e da representação do estado.06
ESPECTRO DE DECISÃO

Reactive ↔ Deliberative

A questão não é “qual é melhor?”, mas quanto vale antecipar consequências antes de agir.

REACTIVE

Observe → Act

Resposta rápida a mudanças.
Baixo custo de decisão.
Maior risco de decisões míopes.
DELIBERATIVE

Observe → Model → Compare → Act

Considera alternativas e estados futuros.
Permite planejamento de longo prazo.
Mais latência e complexidade.
Sistemas reais frequentemente combinam camadas reativas e deliberativas.07
PLANNING & REPLANNING

Planejar é raciocinar sobre estados futuros

PLAN-AND-EXECUTE

S0 → A1 → S1 → A2 → Goal

Um plano é criado e executado enquanto as hipóteses continuam válidas.

commitment
DYNAMIC REPLANNING

Plan → Act → Observe → Replan

O agente revisa o plano quando o mundo muda, uma ação falha ou surgem novas informações.

adaptability
O trade-off central é commitment ↔ adaptability: reconsiderar pouco pode tornar o plano obsoleto; reconsiderar o tempo todo também custa.
Planning prepara o terreno para workflows dinâmicos e coordenação.08
ANATOMIA TÉCNICA

State, memory, actions e boundaries

A teoria se materializa em componentes que sustentam decisões e controlam o espaço de autonomia.

STATE

Situação atual

Dados necessários para continuar a execução sem “começar do zero”.

MEMORY

Informação preservada

Conhecimento que sobrevive além da observação imediata.

ACTION SPACE

O que é possível

Ferramentas, APIs, delegação e operações disponíveis.

BOUNDARIES

O que é permitido

Permissões, budgets, timeouts, max steps e aprovação humana.

Autonomia significa decidir dentro de fronteiras — não liberdade irrestrita.09

A2A: Como o Protocolo Funciona
UM PADRÃO ABERTO PARA AGENTES INDEPENDENTES DESCOBRIREM CAPACIDADES, DELEGAREM TRABALHO E TROCAREM RESULTADOS.
Agent2Agent Protocol14
A2A • DEFINIÇÃO

O agente remoto pode continuar sendo uma caixa-preta

O cliente não precisa conhecer modelos, ferramentas ou memória internos. Precisa conhecer capacidades, contrato de interação e estado do trabalho.

DISCOVER

“O que você sabe fazer?”

Capacidades publicadas permitem decidir se vale delegar.

DELEGATE

“Execute este trabalho.”

A interação cria ou atualiza uma unidade de trabalho identificável.

RECEIVE

“Aqui está o resultado.”

O trabalho produz mensagens, estados e artifacts sem expor a implementação.

A2A padroniza interoperabilidade entre agentes; não define como cada agente decide internamente.

A2A conecta boundaries; não substitui planning, routing ou orchestration.17

WORKFLOW PATTERNS

A pergunta central: quem decide o próximo passo?

Patterns organizam execução; workflows se tornam mais dinâmicos quando o controle é resolvido em runtime a partir do estado.

SEQUENTIAL

A → B → C

Caminho conhecido previamente.

ROUTING

A → Router → ?

O próximo worker depende da entrada ou estado.

PARALLEL

Fan-out / Fan-in

Trabalhos independentes executam e convergem.

ORCHESTRATOR

Plan → Workers

Subtarefas e responsáveis podem ser definidos dinamicamente.

Static → Conditional → Dynamicdesign-time control ─────→ runtime control
Workflow dinâmico não é sinônimo de agente; é uma dimensão de controle.20
PRODUCTION SCENARIOS

Em produção, autonomia encontra o sistema real

Persistência, falhas parciais, retries, concorrência e permissões passam a determinar a confiabilidade.

CUSTOMER SUPPORT

SOFTWARE ENGINEERING

Planning, replanning e rollback.

OPERATIONS

Bounded autonomy

alert → diagnose
safe? → run
    └→ escalate

Approval gates e blast radius.

Prototype → Production: persistence • retries • idempotency • timeouts • concurrency • permissions
Agentes complexos herdam problemas clássicos de sistemas distribuídos.21
MODELO MENTAL FINAL
Agência decide. Multi-agent coordena. A2A interoperabiliza.
O comportamento nasce do ciclo observar → representar → decidir → agir. Multi-agent adiciona boundaries e coordenação; A2A padroniza a colaboração entre esses boundaries; produção adiciona controles e confiabilidade.
